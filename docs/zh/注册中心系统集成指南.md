# 注册中心对接系统集成指南

注册中心通过独立 HTTPS 端口提供集成接入面。默认推荐 OAuth 2.0 Client Credentials 获取 Access Token，并使用标准请求头：

```http
Authorization: Bearer <access-token>
```

注册中心是 OAuth 2.0 Resource Server，只验证令牌，不签发令牌，也不实现浏览器登录流程。可选的取 token 接口将调用方认证及令牌签发委托给目标 IAM 系统。

配置文件分工：`server.conf` 放开关、监听地址、认证模式、IAM 地址及凭据/证书引用；`server.properties` 放超时、缓存、限流、封禁和 scope 授权策略。以下示例按文件拆分，同一键只定义一次。

## 认证方式

### OAuth 2.0 JWT

`etc/conf/server.conf`:

```properties
integration.auth.mode=oauth2_jwt
integration.auth.fingerprint_key=${INTEGRATION_FINGERPRINT_KEY}
integration.oauth2.issuer=https://iam.example.com
integration.oauth2.audience=registry-center
integration.oauth2.jwks_uri=https://iam.example.com/.well-known/jwks.json
```

`etc/conf/server.properties`:

```properties
integration.oauth2.algorithms=RS256
integration.auth.scope_role.registry.admin=nms_oss
integration.auth.scope_role.registry.vendor=vendor_agent
integration.auth.scope_role.registry.read=partner_service
integration.auth.scope_role.registry.audit=analytics_tool
```

系统校验签名、算法、issuer、audience、有效期和生效时间，并通过 `kid` 支持 JWKS 密钥轮换。有界键集缓存最长保留 300 秒，未知 kid 触发刷新，获取失败不延长缓存寿命。需要逐请求检查撤销时应使用 introspection。未映射的 scope 不授予权限。

### OAuth 2.0 Token Introspection

`etc/conf/server.conf`:

```properties
integration.auth.mode=oauth2_introspection
integration.auth.fingerprint_key=${INTEGRATION_FINGERPRINT_KEY}
integration.oauth2.introspection_uri=https://iam.example.com/oauth2/introspect
integration.oauth2.client_id=${OAUTH_INTROSPECTION_CLIENT_ID}
integration.oauth2.client_secret=${OAUTH_INTROSPECTION_CLIENT_SECRET}
integration.oauth2.issuer=https://iam.example.com
integration.oauth2.audience=registry-center
integration.oauth2.ca_file=
```

`etc/conf/server.properties`:

```properties
integration.oauth2.cache_seconds=0
integration.oauth2.cache_max_entries=1024
integration.oauth2.timeout_seconds=3
```

该模式用于 opaque token，也适用于需要在线撤销校验的 JWT。必须验证 IAM 的 HTTPS 证书和主机名。默认**每次数据访问都调用 IAM introspection，不缓存结果**。IAM 决定有效性、过期和撤销；注册中心另行约束 issuer、audience、时间字段及 scope 到角色映射。私有 CA 通过挂载的 `integration.oauth2.ca_file` 指定，留空使用系统根证书（JWT 模式也支持此 CA 配置）。

只有业务明确接受撤销生效延迟时，才开启 `1..60` 秒短缓存；LRU 容量默认 1024，缓存绝不超过 `exp`，没有 `exp` 的结果每次重新校验。JWT 本地验签无法在令牌到期／密钥变化前感知撤销；要求逐次向目标系统确认合法性时应选择 introspection。

## 可选的取 token 接口

`POST /integration/v1/oauth2/token` 仅存在于独立的集成 HTTPS 端口，默认关闭并返回 404；主端口行为不变。配置监听端口、TLS、上述 introspection 及角色映射后，增加：

`etc/conf/server.conf`:

```properties
integration.enabled=true
integration.token.enabled=true
integration.token.provider=oauth2_client_credentials
integration.token.endpoint=https://iam.example.com/oauth2/token
integration.token.ca_file=
```

`etc/conf/server.properties`:

```properties
integration.token.allowed_scopes=registry.read registry.vendor
integration.token.default_scope=registry.read
integration.token.timeout_seconds=3
```

调用方使用**自己在 IAM 注册的** `client_id`／`client_secret`，通过 `client_secret_basic` 认证，不要求预先持有 Bearer Token。注册中心不使用共享高权限账号替所有调用方获取令牌，也不接受请求方传入 IAM 地址。IAM 必须独立限制每个客户端可申请的 scope，并使令牌 audience 面向 `registry-center`；网关 `allowed_scopes` 只是额外上限，不代替 IAM 授权。签发与校验接口必须对应同一个 issuer／资源。每个令牌选择映射到单一角色的 scope，冲突角色会被拒绝。

请求体为 `application/x-www-form-urlencoded`，仅支持 `grant_type=client_credentials` 和可选 `scope`。拒绝 body／query 凭据、重复参数、其他 grant 和越权 scope。含特殊字符的客户端标识／口令，需要先分别 form 编码再 Basic 编码（RFC 6749 §2.3.1）；下面的简化 curl 示例假定凭据仅含非保留字符。

```bash
curl -u "$CLIENT_ID:$CLIENT_SECRET" \
  -d 'grant_type=client_credentials&scope=registry.read' \
  https://registry.example.com:5001/integration/v1/oauth2/token
```

成功返回标准 OAuth JSON：`access_token`、`token_type=Bearer`、`expires_in`、`scope`，并设置 `Cache-Control: no-store`／`Pragma: no-cache`。IAM 必须返回正整数 `expires_in`；代理保守扣除获取耗时。返回 scope 不能超出申请范围，忽略 refresh token 及非标准字段。获取的 token 和调用方口令均不持久化、不缓存；令牌过期后由调用方重新申请，不自动续期。监听端口要求 mTLS 时，取 token 的调用方同样需要有效客户端证书。

私有签发协议通过独立 `TokenAcquisitionProvider` 和 `register_token_acquisition_provider(id, factory)` 扩展，在启动监听器之前注册；不复用／混合 `AuthenticationProvider`。适配器必须向 IAM 验证当前调用方、映射安全 OAuth 错误，返回带有效期和 scope 的 `AcquiredToken`，不得替换为共享服务账号令牌。下游协议不同，不影响第三方统一的 REST／Bearer 接入方式。

独立部署可参考 `etc/conf/server.conf.example`；认证和取 token 配置中的 `${ENV_VAR}` 会解析为环境变量。真实凭据不得提交。

### 静态 Bearer Token

没有 OAuth 2.0 服务时可以使用静态 Bearer Token。凭证文件只保存 HMAC-SHA-256 摘要：

```properties
credential.operations.identity=operations-service
credential.operations.token_hash=<64位小写十六进制摘要>
credential.operations.role=nms_oss
```

配置：

```properties
integration.auth.mode=static_bearer
integration.auth.fingerprint_key=${INTEGRATION_FINGERPRINT_KEY}
integration.auth.static.hmac_key=${INTEGRATION_TOKEN_HMAC_KEY}
integration.credential.file=etc/conf/integration_credentials.conf
```

使用 `python -m agent_registry.integration.token_digest` 交互式生成摘要。不要把明文 Token 写入配置、命令行、日志或审计记录。

### mTLS

```properties
integration.auth.mode=mtls
integration.client_cert=true
```

证书身份来自 TLS 握手得到的真实对端证书，不使用 HTTP 头模拟。证书 CN 在凭证文件中映射：

```properties
credential.vendor.identity=vendor-service
credential.vendor.cn=vendor-service.example
credential.vendor.role=vendor_agent
```

## OAuth 2.0 Client Credentials 示例

先从授权服务器获取 token：

```bash
curl -u "$CLIENT_ID:$CLIENT_SECRET" \
  -d 'grant_type=client_credentials&scope=registry.read' \
  https://iam.example.com/oauth2/token
```

再调用注册中心：

```bash
curl -H "Authorization: Bearer $ACCESS_TOKEN" \
  https://registry.example.com:5001/integration/v1/agent-cards
```

## 响应与安全语义

- `401`：凭证缺失、格式错误、无效、过期或已撤销；取 token 认证失败返回 `invalid_client`。
- `403`：身份有效，但 scope 映射后的角色无权执行操作。
- `429`：请求达到 IP 预认证、签发凭据预算或已认证身份级限流阈值。签发前使用进程私有 HMAC 凭据指纹限制尝试，仅 IAM 认证成功的调用才能扣减身份额度，避免伪造 client_id 污染他人额度。限流为进程内状态，重启后重置；多副本需要统一限流存储或网关。
- `503`：IAM 超时、网络／TLS 故障、无法消费的取 token 响应或 provider 故障；仍拒绝访问，但不累计认证失败封禁。
- 仅成功取 token 响应返回完整 Token；错误、日志和审计不包含完整 Token／口令。共享 Uvicorn 访问日志统一移除 URL 查询内容，覆盖错误路由、代理路径前缀及主监听器重配置；保留路径日志，使用结构化审计追踪认证后的操作。
- JWT、introspection 和静态 Token 均 fail closed。

取 token 接口采用 OAuth `{"error": "..."}` 错误格式，数据接口沿用现有注册中心错误封装。Bearer 401／403 带 `WWW-Authenticate`，取 token 401 使用 Basic challenge。凭据禁止放在 URL；运维可信 IAM 端点可以配置固定非敏感查询参数（例如 api-version），客户端不能改变目的地址。取 token 请求体限制 8 KiB 和十秒（超量 413、慢请求体 408）；获取／校验／JWKS 响应均限制 64 KiB，内置 IAM 传输统一校验 TLS，禁止重定向和环境代理。签发整体期限也约束自定义异步 provider，适配器必须配合取消，不自动重试签发请求。TLS 先于 provider 创建完成预检；启动失败明确上报，并在启动失败与停止时关闭监听器拥有的资源。

验证命令：`python -m pytest -q tests/test_token_acquisition.py tests/test_introspection_lifecycle.py tests/test_integration_oauth_review_regressions.py`，再执行 `python tests/integration_oauth_smoke.py`。smoke 启动真实服务、隔离 SQLite 和合成 HTTPS IAM，验证获取、固定端点查询参数、访问、过期／撤销、角色限制、故障恢复及查询脱敏后的路径日志。该验证不代替具体生产 IAM 的联调认证。

## 私有认证协议

非标准业务消息头不属于核心认证契约。通过 `CredentialExtractor` 和 `AuthenticationProvider` 扩展注入，参考 `samples/custom_auth_provider.py`。扩展必须返回统一 `Principal`，后续授权、限流、封禁和审计不会读取业务私有消息头。

`register_authentication_provider(provider, extractor)` 注册的是共享、业务拥有的实例，而不是工厂。主端口与集成端口的 handler 可能在不同事件循环并发调用它们；handler 不会关闭自定义认证 provider。扩展应保持无状态，或确保跨线程／事件循环安全，不得在监听器之间共享绑定单一事件循环的异步客户端；资源创建与释放由业务组合入口负责。内置认证 provider 则按监听器分别创建。这里描述的是认证 provider 的所有权，不改变上文独立的 token 签发 provider 生命周期。

仅在确认调用方凭据非法时抛出带明确非法凭据原因的 `AuthenticationError`。未归类的网络／内部异常和 provider 错误返回值均失败关闭为 503，不累计封禁。自定义签发 provider 必须为异步且配合取消，在 `aclose()` 释放拥有的客户端；同步阻塞工作不得直接运行在事件循环。

## 迁移

原私有双消息头认证不再由核心实现。迁移时优先接入 OAuth 2.0 Client Credentials；暂时无法迁移的业务可将旧协议封装为自定义 extractor/provider，并在业务启动代码中注册。集成方业务 API 路径与四角色授权矩阵保持不变。
